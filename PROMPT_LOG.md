# Prompt-log (хронология работы над MVP)

> Важно: ниже приведена реконструкция по фактической истории обсуждения проекта, а не дословная выгрузка всех сообщений платформы. 

| № | Этап и запрос (краткое содержание) | Решение ИИ | Статус | Что сделано командой / комментарий |
|---|---|---|---|---|
| 1 | «Нужно, чтобы MVP закрывал один из рисков, опирался на мои источники и имел максимально простой код» | Предложена простая анкета + словарь правил + отчёт | Принято | Зафиксирована архитектура без БД и интеграций |
| 2 | «Методичка запрещает атаковать систему и проверять уязвимости без письменного согласия; сложных интеграций быть не должно» | Отказ от сканирования, безопасная самооценка | Принято как обязательное ограничение | Прототип не выполняет сетевые запросы и не проверяет инфраструктуру |
| 3 | «Внешний периметр реально отсканировать не можем, но можно сделать тренажёр аудита» | Сценарий тренажёра: пользователь вводит сведения, система сверяет их с чек-листом | Принято | Выбрана модель анкетной оценки |
| 4 | «Пользователь вводит данные об инфраструктуре, система сопоставляет их с рисками и выдаёт рекомендации» | Предложена форма, набор условий, отчёт | Принято | Реализованы вопросы и условные правила |
| 5 | «Рекомендации должны опираться на Solar» | Привязка каждого правила к источнику и разделу | Принято, расширено до собственных SRC-016—SRC-020 | Используются только первоисточники из аналитического отчёта |
| 6 | «Нужна полноценная веб-форма, данные строго из предоставленного файла» | Предложен чек-лист по MFA, FIDO2, RDP/VPN, панелям, PAM/JIT, NHI, DNS/EDR, резервным копиям | Принято после сверки с аналитическим отчётом | Уточнено, что наличие VPN/RDP само по себе не является уязвимостью |
| 7 | «Нужен код, чтобы скопировать публичную ссылку, например HTML; обязательны README, prompt-log, демо и презентация» | Переход от Python/Streamlit к автономному HTML-файлу и комплекту артефактов | Принято | Один файл открывается локально; публичный URL выдаёт хостинг после загрузки |

## Принятые варианты

- Статический HTML/CSS/JavaScript вместо Python/Streamlit: меньше зависимостей, достаточно для демонстрации на заранее подготовленных данных.
- Словарь/правила в JavaScript вместо базы данных.
- Три демонстрационных профиля вместо подключения к реальной инфраструктуре.
- «Не знаю» выводится отдельно, а не трактуется как отсутствие меры.
- Не вводится единый процент защищённости, поскольку исходный аналитический отчёт не задаёт валидированную количественную методику.

## Отклонённые варианты

- Активное сканирование внешнего периметра, проверка портов и уязвимостей — отклонено из-за методических ограничений и отсутствия письменного согласия.
- Сложные интеграции, API, парсинг, серверная база данных — отклонены как избыточные для демо.
- Python + Streamlit как обязательная реализация — отклонено после уточнения требования о копируемом HTML и публичной ссылке.
- Выдуманный рейтинг/процент защищённости — отклонён из-за отсутствия методики в исходных источниках.
